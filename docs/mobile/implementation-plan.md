# Android 远程运行客户端

用户要求：基于引用会话 `01a1c024-b09f-7043-89ca-c53a7b415e7b`，参照本机 Orchester 手机应用实现一致的 Android UI、布局和风格，连接 Sandkasten 远程执行服务，在本机测试；按任务分步提交、验证、推送并合并 main。

## 提交与验证

1. HTTP 取消接口：`POST /v1/jobs/{job_id}/cancel`，沿用 API 认证和错误处理；Go API / jobs 测试。已有提交 `a956431`。
2. 手机业务与界面：四导航、六主题、主题化选择面板、单双栏；多设备令牌连接、动态运行时目录、本机源码项目、输入/参数/文件、远程执行、完整输出、停止与重连恢复；Vitest、类型检查和生产构建。
3. Android 工程：独立身份、桌面同源图标、暗色启动、安全区、键盘与系统返回；Keystore 凭据；APK、原生测试包、lint，以及安装版测试。
4. 验收与维护：操作文档、可复现原生 E2E、质量脚本与 Android CI；真实 API + Postgres + Rust 沙箱的安装版运行/编译失败/取消/重启验收；核对 APK 内容和哈希，推送分步提交，合并 main 并核对远端。

验收中另行拆分两项修复：HTTP `outputReady` 标识避免取消状态先于输出落库时停止查询；Rust 沙箱保留取消前已收集的输出和统计，同时继续终止、回收进程及后代。手机双栏编辑区的重复内边距及窄栏动作按钮也按独立提交修复并复验。

## 范围依据

Orchester 的四个一级页面、六套主题 token、留白、圆角卡片、宽触摸区域、底部导航、底部选择面板和启动体验作为视觉参考。业务调用 Sandkasten 已有 HTTP API：`GET /v1/runtimes`、`POST /v1/run`、`GET /v1/jobs/{id}` 和取消接口。设备认证使用 `SANDKASTEN_API_TOKEN`；项目在手机编辑并上传源码，不调用参考应用的 Agent、配对码或文件浏览协议。

API 没有列出全部历史任务的接口，手机历史只包含该安装提交并保留的任务 ID。重新连接时从电脑重新读取状态和输出；关闭工作栏只改变手机界面。支持全部服务端目录中的运行时，执行能力由连接的运行器配置决定。
